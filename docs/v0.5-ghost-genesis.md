# Ghost Flux Computer v0.5: Ghost Genesis

## Research question

Can a bounded **evolutionary program synthesis** mechanism create topology-only
spanning-forest ranking rules that were not in our original six hand-designed
policies, and do those rules outperform classical baselines on unseen graphs?

GFC reads a cycle-space flux obstruction for binary XOR edge constraints.
That theorem, and its O(n+m) constructive SAT/UNSAT certification, are known.
Ghost Genesis explores adaptive **readout layouts**, not new complexity classes.

## Search language (safe grammar)

A genome is four signed integers `(w0,w1,w2,w3)`, each in [-6,6]. It scores
an edge by a linear combination of topology features:

```
score(e) = w0 * (deg(u)+deg(v))
         + w1 * |N(u) intersect N(v)|
         + w2 * |deg(u)-deg(v)|
         + w3 * deg(u)*deg(v)/max(1,n)
```

Edges sorted by descending score are processed by Kruskal-style union/find
to construct a spanning forest. Non-tree edges complete fundamental cycles.
Feature extraction and ranking never inspect XOR edge bits. Mutation changes
one or two coefficients; uniform crossover combines parental coefficient
vectors. Evolution uses cached candidate training losses, elitism, seeded
random tie resolution, and repeated candidate generation.

Fitness on training graphs is mean of normalized `sum(cycle_lengths)/(m*n)`.
Generated rules are verifiably syntactically new when their vector is not
among the six initial vectors. Syntactic novelty is not mathematical novelty.
We also report whether the produced cycle basis differs from all six fixed
policy readouts on an unseen graph.

## Experimental design

Run with standard-library Python 3.10+:

```bash
python -m unittest discover -v
python benchmark_genesis.py --train-per-family 12 --test-per-family 32 --generations 12 --population 20 --memory-out genesis_memory.json > genesis_results.json
```

Train on disjoint, seeded modular/dense/hub/grid graph sets.
Test on held-out samples from each training family, and a random-graph
distribution shift. Each test graph uses the **same tie seed** across
candidates and policies.

Comparison methods:

- random spanning forest via existing `random` policy
- fixed `hub` policy
- **v0.4 meta-memory**, trained on exactly the same training instances
- **BFS spanning forest** (standard, simple classical layout)
- **posthoc oracle of all six** original policies, evaluating every candidate
  on the test graph. This oracle is only an upper-bound reference on potential
  and **is not deployable without test-set search**.

In addition to total fundamental-cycle edge visits, report per-graph wins,
ties, losses versus hub; frequency of genuinely distinct layouts; and number
of graphs on which the evolved genome beats all six original policies.

## Strict correctness

Every readout is produced from a spanning forest. The fundamental cycles
form a basis of the graph's cycle space. Therefore the vector of flux
measurements is zero iff the graph is satisfiable. The independent
`gfc.certify` and verification routines remain unchanged. Tests verify
topology/constraint-bit blindness, loops, multiedges, disconnected graphs,
randomized certificates, JSON persistence, and deterministic search.

## Scientific evaluation limits and failure criteria

1. A rule with new weights is NOT automatically a better rule. Only
   held-out improvement over hub, meta-memory, and BFS would be convincing
   within the specified proxy.
2. Minimizing fundamental-cycle length is not equivalent to minimizing
   proof-check time, total solver time, information required for a single
   contradiction, or hardware energy.
3. Evolution evaluates many candidates. Training probe visits and total
   training seconds must be reported before calling any advantage economical.
4. Single-pass Python timing is environment-dependent, especially at small
   runtimes; proper end-to-end repeated timing and scaling studies are needed.
5. Report distribution-shift failures rather than hiding them. Synthetic
   graph families do not establish robust transfer on real benchmarks.
6. Compare against a direct O(n+m) satisfiability/certificate traversal for
   practical performance. A readout proxy alone cannot beat this theorem.
7. The grammar is four integer linear weights, not arbitrary new operators or
   autonomous unbounded algorithm discovery.

## First verified Genesis experiment, 2026-10-10

[Audited GitHub Actions run](https://github.com/madowaku/ghost-flux-computer/actions/runs/38021262520)
contains the trained JSON genome and benchmark JSON.

After evolution of 105 distinct genomes on 48 training graphs, the best
genome was **(2,2,0,6)**. This integer vector was not one of the six initial
policy templates. A total of 565,459 cycle-edge visits were counted during
the cached fitness evaluations. Wall-clock training took about 0.95s on this
CI runner, a hardware/environment-dependent estimate.

| Held-out set | Genesis | Fixed hub | v0.4 meta | BFS forest | Oracle of original six |
|---|---:|---:|---:|---:|---:|
| Modular (32) | 1,374 | 1,394 | 1,373 | 1,431 | 1,369 |
| Dense (32) | 7,074 | 7,167 | 7,167 | 7,484 | 7,146 |
| Hub (32) | 2,343 | 2,343 | 2,343 | 2,715 | 2,343 |
| Grid (32) | 2,285 | 2,300 | 2,301 | 3,045 | 2,287 |
| Matched-family mixture (128, fresh tie seeds) | **13,080** | 13,205 | 13,183 | 14,428 | 13,149 |
| Shifted random (32) | 3,795 | 3,804 | 3,804 | 4,023 | 3,728 |

The *matched-family mixture* is reevaluated with a separate seed stream,
so its sum need not equal the sum of the four separately evaluated rows.
For the 128-graph mixture, Genesis improved upon fixed hub in 43 graphs,
tied in 78, and lost in 7. It generated an actually different
**unordered set of fundamental cycles** from all six fixed-policy
readouts in 48 of 128 graphs. It beat the minimum measured cost of
all six legacy policies in 25 of 128 graphs. The six-policy oracle's
test-specific advantage is nondeployable, and Genesis does not always win:
the modular family is slightly worse than v0.4 meta-memory, and the
shifted random-family advantage over hub is only about 0.24%.

**Crucial performance reality check:** on the 128-graph mixture,
single-pass Python timing without graph preparation/features was
about 0.0242s for Genesis observation versus 0.0052s for the direct
linear-time XOR certifier. Even this incomplete comparison gives
**no evidence of end-to-end speedup**. The cycle-length proxy is not
computational wall-clock time, and any approach must count training,
data preparation, search, and readout costs. A generated weighting
rule is not an undiscovered computational principle.

The Python tests also passed in 3.10 and 3.12. This result is a
research prototype with controlled synthetic evidence, not proof of a
hardware architecture advantage.

## Next extension

A future v0.6 may search *verified algebraic rewrites* of cycle-basis
observations and optimize minimal odd-parity witness size, rather than simply
the total number of fundamental-cycle edges. Each rewrite must preserve a
checkable certificate and be compared to established cycle algorithms.
