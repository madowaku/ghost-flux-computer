# GFC v0.3: Ghost Memory

## Question
Can an observation layout rule learned from earlier XOR-constraint graphs be
reused on never-seen graphs, without compromising exact parity certificates?

This prototype uses **finite policy selection**, not an autonomous algorithm
inventor. A "memory" is a serializable record of one learned graph-topology
policy. The underlying XOR graph satisfiability theorem is established math.

## Formalization

Let `G=(V,E)`, with edge constraints `x_u XOR x_v = b_e`.
For policy `p`, build a spanning forest `T_p(G)`, then measure the XOR flux
of every corresponding fundamental cycle. Define readout cost proxy

```
C_p(G) = sum(len(cycle) for cycle in fundamental_cycles(T_p(G)))
```

Candidate policies: random, hub, anti_hub, triangle, hub_triangle, low_triangle.
All features use only topology (vertex degree and shared-neighbor counts),
never edge parity labels. Ties are pseudo-random with a recorded seed.

Across training graphs `G_1...G_N`, select

```
p* = argmin_p mean_k C_p(G_k) / max(1, |E_k| * max(1, |V_k|))
```

This bounded empirical loss in [0,1] supports finite-class generalization
analysis, but no distribution-free claim that a particular policy beats
random on every unseen graph. For i.i.d. samples, a union-bound Hoeffding
result controls each policy's absolute true-vs-empirical risk gap by
`sqrt(log(2*6/delta)/(2*N))` with probability at least `1-delta`.
That bound is likely loose for this small demonstration.

## Exactness and independent verification

Changing the spanning forest changes the **coordinates** of a cycle flux
signature, but not whether the signature is identically zero.
`gfc.certify` separately returns an assignment or an XOR-inconsistent
even-degree edge-set certificate, checkable by `verify_assignment` or
`verify_conflict`.

The self-tests additionally check random graphs, self-loops, parallel edges,
independence from the parity labels when constructing an observation layout,
and save/restore of memory JSON.

## Repeatable run

Requires only Python >= 3.10, without pip dependencies.

```bash
python -m unittest discover -v
python benchmark_memory.py --train 48 --test 64 --memory-out ghost_memory.json > benchmark_results.json
```

Training is 48 independently generated hub-family graphs (seed 1001). The
learned policy is tested on two separate sets of 64: a matched hub-family
sample (seed 1002) and a shifted grid-family sample (seed 1003).
Seeded vertex relabeling prevents a trivial reliance on node IDs.
Each graph includes XOR constraints; constraint labels do not influence
readout policy choice.

Outputs include saved learned policy, normalized in-sample losses,
held-out random baseline, learned-policy costs, fixed hub heuristic cost,
and a distribution-shift comparison.

The optimistic break-even **proxy** is calculated as:

```
extra training cycle-edge visits / mean future cycle-edge visits saved
```

It does not account for policy feature extraction, sorting, architecture
switching, solver time, or the costs of collecting the training set.
The fairer end-to-end timing/energy comparison is a next milestone.
The random policy is an intentionally weak baseline; a fixed hub policy is
also reported to show whether training improves on a simple prechosen rule.

## Falsification checklist

- If the trained policy fails to outperform both the random *and* fixed-hub
  heuristic on held-out matched-family data, the empirical advantage is weak.
- If the shifted grid dataset reverses improvements, transfer is
  distribution dependent, not generally portable.
- If policy selection time + implementation cost exceeds saved measurements,
  there is no amortized practical benefit.
- If independent parity certificate tests fail, no performance result counts.
